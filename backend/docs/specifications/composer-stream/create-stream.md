# Спецификация поведения: Создание стрима

## Назначение и полезный результат

Композитор планирует новый стрим на конкретную дату с определённым типом. Результат — сохранённый стрим в статусе «Запланирован», который затем можно запустить и использовать для ведения заказов.

## Границы и условия использования

- Описываемое поведение: создание одной записи стрима.
- Инициатор и запуск: аутентифицированный пользователь с ролью «Композитор» вызывает операцию создания.
- Допустимые условия: вызывающая сторона передаёт дату проведения и тип стрима; дата не предшествует текущей дате, тип относится к допустимым бизнес-значениям.
- Вне scope: запуск, завершение и отмена стрима; выборки стримов; создание и обработка заказов.

## Входные данные

- `EventDate` — дата проведения стрима (`DateOnly`), обязательна. Допустимое значение — текущая или будущая дата.
- `Type` — тип стрима, обязателен. Допустимые значения: `Donation`, `Debt`, `Charity`. Значение `Unspecified` и значения вне перечисления недопустимы.

## Наблюдаемое поведение

- Корректный запрос → стрим создаётся и сохраняется, ответ — созданный стрим с состоянием:
  - `Status` = `Planned`;
  - `Type` и `EventDate` совпадают с запросом;
  - `StartedAt` и `CompletedAt` не заданы (`null`);
  - `Id` присвоен хранилищем;
  - создатель — пользователь, выполнивший запрос.
- `EventDate` раньше текущей даты → запрос отклоняется, стрим не создаётся.
- `Type` равен `Unspecified` или не входит в перечисление → запрос отклоняется, стрим не создаётся.
- На `EventDate` уже существует стрим (в любом статусе, включая `Canceled` и `Completed`) → запрос отклоняется с конфликтом, новый стрим не создаётся, существующий не изменяется.
- Вызывающий не аутентифицирован → отказ доступа; аутентифицирован, но не имеет роли «Композитор» → отказ доступа; стрим не создаётся.
- Успешное создание уведомляет подсистему очереди заказов о появлении стрима.

## Правила и инварианты

1. В любой момент времени на одну дату проведения существует не более одного стрима, независимо от его статуса. Дата, занятая отменённым или завершённым стримом, остаётся занятой навсегда.
2. Каждый успешно созданный стрим находится в статусе `Planned`.
3. Создателем стрима становится пользователь, выполнивший запрос.
4. Дата проведения не может быть раньше текущей даты (UTC).
5. Тип стрима должен быть одним из бизнес-значений перечисления, отличным от `Unspecified`.
6. Операция не идемпотентна: повторный вызов с той же датой отклоняется с конфликтом, а не возвращает ранее созданный стрим.

## Принятые ограничения

- Уникальность даты проведения обеспечивается хранилищем и действует глобально, а не только для создателя.
- Отказ не оставляет частичных изменений: при любом предусмотренном отказе новый стрим не сохраняется.

## Примеры приёмки

### Успешное создание

Дано:

- действующий пользователь с ролью «Композитор»;
- текущая дата — `2026-09-11`;
- на `2026-09-20` стримов нет.

Когда:

- вызывается создание с `EventDate = 2026-09-20`, `Type = Donation`.

Тогда:

- ответ содержит созданный стрим: `EventDate = 2026-09-20`, `Type = Donation`, `Status = Planned`, `StartedAt = null`, `CompletedAt = null`, ненулевой `Id`;
- стрим сохранён; дата `2026-09-20` считается занятой.

### Дата в прошлом

Дано:

- действующий пользователь с ролью «Композитор»;
- текущая дата — `2026-09-11`.

Когда:

- вызывается создание с `EventDate = 2026-09-10`.

Тогда:

- запрос отклоняется как некорректный вход;
- стрим не создаётся; дата `2026-09-10` остаётся свободной.

### Недопустимый тип

Дано:

- действующий пользователь с ролью «Композитор»;
- дата `2026-09-20` свободна.

Когда:

- вызывается создание с `EventDate = 2026-09-20`, `Type = Unspecified`.

Тогда:

- запрос отклоняется как некорректный вход;
- стрим не создаётся.

### Дата занята отменённым стримом

Дано:

- действующий пользователь с ролью «Композитор»;
- на `2026-09-20` существует стрим в статусе `Canceled`.

Когда:

- вызывается создание с `EventDate = 2026-09-20`, `Type = Debt`.

Тогда:

- запрос отклоняется с конфликтом;
- новый стрим не создаётся; существующий стрим остаётся без изменений в статусе `Canceled`.

### Недостаточно прав

Дано:

- аутентифицированный пользователь без роли «Композитор».

Когда:

- вызывается создание с корректными `EventDate` и `Type`.

Тогда:

- доступ запрещён;
- стрим не создаётся.

## Техническая привязка

- Операция: `POST /api/ComposerStream/Create`, `[AuthorizeComposer]` (роль `Composer`).
- Запрос: `Faryma.Composer.Api.Features.ComposerStream.Create.CreateRequest` (`EventDate`, `Type`).
- Ответ: `Faryma.Composer.Api.Features.ComposerStream.Create.CreateResponse` с `ComposerStreamDto`.
- Тип: `Faryma.Composer.Domain.Enums.ComposerStreamType`; статус: `Faryma.Composer.Domain.Enums.ComposerStreamStatus`.
- Конфликт даты возвращается как ошибка бизнес-логики (HTTP 409); некорректный вход — HTTP 400.

# Use case: Запустить стрим

## Полезный результат

Запланированный стрим становится текущим идущим: композитор ведёт эфир, заказы этого стрима обслуживаются как актуальные.

## Участник и момент запуска

- Участник: композитор
- Триггер: намерение начать эфир выбранного стрима
- Предусловия: стрим существует; дата проведения совпадает с сегодняшней; статус `Planned` либо стрим уже `Live`; другого идущего стрима нет

## Входные данные

- `ComposerStreamId` — идентификатор существующего стрима

## Наблюдаемый результат

При успехе:

- Статус стрима — `Live`
- Зафиксировано время начала
- Возвращается этот стрим
- Очередь считает этот стрим текущим и пересчитывает позиции заказов, созданных в нём

При невозможности выполнения:

- Стрим не найден → операция не выполняется
- Дата проведения не сегодня → стрим не запускается, состояние не меняется
- Другой стрим уже `Live` → выбранный стрим не запускается
- Статус `Completed` или `Canceled` → стрим не запускается

## Бизнес-правила

1. В `Live` можно перевести только стрим в статусе `Planned`.
2. Запустить можно только стрим, дата проведения которого совпадает с сегодняшней датой приложения.
3. Одновременно может быть только один стрим в статусе `Live`.
4. Тип стрима на запуск не влияет.
5. Повторный запрос: если стрим уже `Live`, система возвращает его без изменений и без повторной фиксации времени начала.

## Различающие сценарии

- Если стрим `Planned` и дата проведения — сегодня, система переводит его в `Live`.
- Если стрим `Planned` и дата проведения — вчера или завтра, система отклоняет запуск.
- Если этот стрим уже `Live`, система возвращает его как есть.
- Если `Live` уже другой стрим, система отклоняет запуск выбранного, даже если его дата — сегодня.

## Принятые ограничения

- Бизнес-ограничения: запуск разрешён только в день проведения; одновременно один идущий стрим
- Технические ограничения: «сегодня» и момент старта берутся из часов приложения
- Вне scope: создание, завершение и отмена стрима; взятие заказа в работу; правила приоритета очереди

## Основания спецификации

### Решения

- Запуск отклоняется, если дата проведения стрима не совпадает с сегодняшней

### Факты

- Запуск существует как операция композитора и меняет статус `Planned` → `Live` с фиксацией времени начала
- Повторный запуск уже `Live` стрима сейчас возвращает его без изменений
- Пока есть другой `Live` стрим, запуск отклоняется
- `Completed` и `Canceled` запустить нельзя
- После успешного перехода в `Live` очередь получает сигнал, что стрим начат
- Проверки даты в коде ещё нет, в обработчике оставлен TODO

### Предположения

- Повторный запрос к уже `Live` стриму остаётся идемпотентным успехом, даже если календарный день уже сменился
- Статусы заказов в хранилище при запуске не меняются; меняется только расчёт очереди
- Часы приложения — `DateTimeContext` (`Today` / `Now` от UTC)

## Примеры приёмки

### Успешный запуск

Дано:

- Сегодня 30 августа
- Стрим в статусе `Planned`, дата проведения 30 августа
- Другого `Live` стрима нет

Когда:

- Композитор запускает этот стрим

Тогда:

- Статус — `Live`, время начала зафиксировано
- Возвращается этот стрим
- Очередь считает его текущим

### Повторный запуск уже идущего стрима

Дано:

- Стрим уже в статусе `Live`, время начала задано

Когда:

- Композитор снова запускает этот стрим

Тогда:

- Статус и время начала не меняются
- Возвращается тот же стрим

### Дата проведения не сегодня

Дано:

- Сегодня 30 августа
- Стрим в статусе `Planned`, дата проведения 31 августа

Когда:

- Композитор запускает этот стрим

Тогда:

- Операция отклоняется
- Статус остаётся `Planned`, время начала не задано

### Уже идёт другой стрим

Дано:

- Стрим A в статусе `Live`
- Стрим B в статусе `Planned`, дата проведения — сегодня

Когда:

- Композитор запускает стрим B

Тогда:

- Операция отклоняется
- Стрим B остаётся `Planned`
- Стрим A остаётся `Live`

### Завершённый стрим

Дано:

- Стрим в статусе `Completed`, дата проведения — сегодня

Когда:

- Композитор запускает этот стрим

Тогда:

- Операция отклоняется
- Статус остаётся `Completed`

## Техническая привязка

- Точка входа: `POST api/ComposerStream/Start`
- Авторизация: роль композитора (`AuthorizeComposer`)
- Транзакционная граница: сохранение стрима до сигнала очереди
- Идемпотентность: повтор для `Live` возвращает сущность без `SaveChanges` и без события очереди
- Изменяемые данные: `ComposerStream.Status`, `ComposerStream.StartedAt`
- Публикуемые события: `OrderQueueUpdateType.StreamStarted` после первого перехода в `Live`
- Требования к консистентности: проверка «нет другого `Live`» и смена статуса в одной операции; дату сверять с `DateTimeContext.Today` до перевода в `Live`

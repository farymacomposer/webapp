# Use case: Отменить стрим

## Полезный результат

Запланированный стрим больше не состоится: он перестаёт быть доступным для запуска и не учитывается как ближайший стрим очереди.

## Участник и момент запуска

- Участник: композитор
- Триггер: композитор отменяет запланированный стрим
- Предусловия: стрим существует

## Входные данные

- `id стрима` — какой стрим отменить; должен указывать на существующий стрим

## Наблюдаемый результат

При успехе:

- статус стрима становится «Отменен»
- дата, тип, момент начала и момент завершения не меняются
- заказы стрима не меняются
- очередь пересчитывает дату ближайшего доступного стрима и позиции заказов
- отменённый стрим больше не входит в список текущего и запланированных стримов
- возвращается отменённый стрим

При невозможности выполнения:

- стрим не найден → ошибка, состояние не меняется
- статус стрима не «Запланирован» и не «Отменен» → ошибка, состояние не меняется
- у стрима есть активные созданные заказы → ошибка, состояние не меняется

## Бизнес-правила

1. Отменить можно только стрим в статусе «Запланирован». Запущенный и завершённый стрим отменить нельзя.
2. Тип стрима на возможность отмены не влияет.
3. Дата проведения на возможность отмены не влияет: прошедший запланированный стрим отменить можно.
4. Активные созданные заказы — заказы, созданные в этом стриме, в статусе «Предзаказ», «Ожидает оплаты» или «Ожидает взятия в работу». Заморозка заказа не снимает этот запрет.
5. Выполненные и отменённые созданные заказы отмене стрима не мешают.
6. Отмена стрима не отменяет и не переназначает заказы.
7. Повторный запрос: если стрим уже отменён, результат тот же, что при успешной отмене; повторного пересчёта очереди нет.

## Различающие сценарии

- Если стрим запланирован и активных созданных заказов нет, система отменяет стрим.
- Если стрим запланирован, но есть хотя бы один активный созданный заказ, система отмену отклоняет.
- Если стрим уже отменён, система возвращает его без ошибки.
- Если стрим запущен или завершён, система отмену отклоняет.

## Принятые ограничения

- Бизнес-ограничения: отмена только из статуса «Запланирован»; при активных созданных заказах отмена запрещена, а не каскадная
- Вне scope: создание, запуск и завершение стрима; отмена и переназначение заказов; указание причины отмены

## Основания спецификации

### Решения

- Описать use case «Отменить стрим» в `docs/use-cases/composer-stream`

### Факты

- Отмена разрешена только из статуса `Planned`; иначе доменная ошибка
- Повторная отмена уже отменённого стрима возвращает стрим без изменения и без события очереди
- Отмена запрещена, если у стрима есть созданные заказы в статусах `Preorder`, `Pending` или `AwaitingPayment`
- После отмены очередь получает событие отмены и пересчитывает ближайший стрим и позиции
- Операция доступна роли композитора; вход — идентификатор стрима

### Предположения

- Текущее поведение кода является целевым контрактом этого use case

## Примеры приёмки

### Успешная отмена запланированного стрима без активных заказов

Дано:

- стрим запланирован
- у стрима нет созданных заказов в статусах «Предзаказ», «Ожидает оплаты», «Ожидает взятия в работу»

Когда:

- композитор отменяет этот стрим

Тогда:

- статус стрима — «Отменен»
- очередь пересчитана относительно следующего доступного стрима
- возвращается этот стрим

### Отмена при активном созданном заказе

Дано:

- стрим запланирован
- в нём есть заказ-предзаказ

Когда:

- композитор отменяет этот стрим

Тогда:

- стрим остаётся запланированным
- заказ не меняется
- возвращается ошибка о невозможности отмены из-за активных заказов

### Повторная отмена

Дано:

- стрим уже отменён

Когда:

- композитор снова отменяет этот стрим

Тогда:

- статус остаётся «Отменен»
- ошибка не возвращается
- возвращается этот стрим

### Отмена запущенного стрима

Дано:

- стрим запущен

Когда:

- композитор отменяет этот стрим

Тогда:

- статус остаётся «Запущен»
- возвращается ошибка о невозможности отмены в текущем статусе

## Техническая привязка — опционально

- Точка входа: `POST api/ComposerStream/Cancel`
- Авторизация: роль композитора
- Транзакционная граница: смена статуса сохраняется до публикации события очереди
- Идемпотентность: повтор для уже отменённого стрима возвращает текущее состояние без события
- Изменяемые данные: статус стрима
- Публикуемые события: `StreamCanceled` — только при фактической смене статуса
- Требования к консистентности: очередь узнаёт об отмене после успешного сохранения

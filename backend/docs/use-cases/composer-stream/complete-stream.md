# Use case: Завершить стрим

## Полезный результат

Запущенный стрим закрывается и больше не считается текущим. Фиксируется момент завершения. Очередь перестраивается под ближайший оставшийся стрим: выполненные в этом стриме заказы уходят из очереди, неразобранные остаются ждать следующего стрима.

## Участник и момент запуска

- Участник: композитор
- Триггер: композитор завершает указанный стрим
- Предусловия: стрим существует; нет заказа в работе. Если стрим уже завершён, повтор допустим и безопасен

## Входные данные

- `id стрима` — какой стрим завершить; должен быть больше нуля

## Наблюдаемый результат

При успехе:

- статус стрима становится «Завершен»
- фиксируются дата и время завершения
- возвращается этот стрим
- очередь получает обновление «стрим завершен»: пересчитывается дата ближайшего стрима; пересчитываются позиции неразобранных заказов этого стрима и выполненных в нём заказов; выполненные в этом стриме заказы покидают очередь

При невозможности выполнения:

- стрим не найден → ошибка «стрим не найден», состояние не меняется
- стрим в статусе «Запланирован» или «Отменен» → ошибка «невозможно завершить стрим в этом статусе», состояние не меняется
- есть заказ в работе → ошибка «невозможно завершить стрим, пока заказ находится в работе», состояние не меняется
- нет роли композитора или нет авторизации → отказ в доступе, состояние не меняется

## Бизнес-правила

1. Завершить можно только запущенный стрим.
2. Пока существует заказ в работе, стрим завершить нельзя: сначала этот заказ нужно выполнить или отменить.
3. Операция не меняет статусы заказов. Неразобранные заказы этого стрима (предзаказ, ожидает оплаты, ожидает взятия в работу) остаются в тех же статусах и в очереди. Замороженные заказы остаются замороженными.
4. Тип стрима на правила завершения не влияет.
5. Повторный запрос: если стрим уже завершён, операция завершается успехом без изменений и без повторного обновления очереди.

## Различающие сценарии

- Если стрим запущен и заказа в работе нет, система завершает стрим.
- Если стрим запущен и есть заказ в работе, система отказывает, даже когда у стрима остались другие неразобранные заказы.
- Если стрим уже завершён, система возвращает его без повторной фиксации времени и без повторного обновления очереди.
- Если стрим запланирован или отменён, система отказывает из-за статуса.
- Если в стриме есть неразобранные заказы, но нет заказа в работе, система завершает стрим и оставляет эти заказы в очереди.
- Если в стриме есть выполненные заказы, после завершения они покидают очередь.

## Принятые ограничения

- Бизнес-ограничения: завершение закрывает уже запущенный стрим; отмена запланированного стрима — отдельная операция
- Технические ограничения: HTTP-ключ идемпотентности не применяется; повтор безопасен только для уже завершённого стрима
- Вне scope: создание, запуск и отмена стрима; выполнение, отмена, заморозка заказа; сам алгоритм приоритетов очереди

## Основания спецификации

### Решения

- Описать существующую операцию завершения стрима, а не проектировать новую

### Факты

- Завершение принимает `id` стрима и доступно только роли композитора
- Домен разрешает переход в «Завершен» только из «Запущен» и записывает момент завершения
- Повтор по уже завершённому стриму возвращает стрим без повторной обработки
- Наличие любого заказа в работе блокирует завершение
- Статусы заказов при завершении стрима не меняются
- После успешного завершения очередь пересчитывается: меняется дата ближайшего стрима; обновляются неразобранные заказы этого стрима и выполненные в нём заказы; выполненные в этом стриме заказы помечаются как покинувшие очередь
- Отдельных тестов на эту операцию нет

### Предположения

- Блокировка «есть заказ в работе» относится к системе в целом: одновременно может быть только один такой заказ, и он принадлежит текущему запущенному стриму

### Открытые вопросы

- Нет вопросов, способных изменить наблюдаемый результат

## Примеры приёмки

### Успешное завершение

Дано:

- стрим запущен
- заказа в работе нет

Когда:

- композитор завершает этот стрим

Тогда:

- статус стрима — «Завершен»
- момент завершения зафиксирован
- возвращается этот стрим
- очередь обновлена как «стрим завершен»

### Повтор по уже завершённому стриму

Дано:

- стрим уже завершён

Когда:

- композитор снова завершает этот стрим

Тогда:

- операция завершается успехом
- статус, момент завершения и очередь не меняются

### Заказ в работе

Дано:

- стрим запущен
- один заказ находится в работе

Когда:

- композитор завершает этот стрим

Тогда:

- операция завершается ошибкой «невозможно завершить стрим, пока заказ находится в работе»
- стрим остаётся запущенным
- очередь не обновляется

### Неразобранные заказы не мешают завершению

Дано:

- стрим запущен
- есть заказы в статусах «предзаказ», «ожидает оплаты» или «ожидает взятия в работу»
- заказа в работе нет

Когда:

- композитор завершает этот стрим

Тогда:

- стрим завершается
- статусы этих заказов не меняются
- заказы остаются в очереди, их позиции пересчитываются под ближайший оставшийся стрим

### Выполненные заказы покидают очередь

Дано:

- стрим запущен
- в этом стриме есть выполненные заказы
- заказа в работе нет

Когда:

- композитор завершает этот стрим

Тогда:

- стрим завершается
- выполненные в этом стриме заказы покидают очередь

### Стрим не в статусе «Запущен»

Дано:

- стрим запланирован или отменён

Когда:

- композитор завершает этот стрим

Тогда:

- операция завершается ошибкой «невозможно завершить стрим в этом статусе»
- состояние стрима и очередь не меняются

### Стрим не найден

Дано:

- стрима с указанным `id` нет

Когда:

- композитор завершает этот стрим

Тогда:

- операция завершается ошибкой, что стрим не найден

## Техническая привязка

- Точка входа: `POST api/ComposerStream/Complete`
- Авторизация: роль `Composer`
- Транзакционная граница: изменение стрима сохраняется до публикации события очереди
- Идемпотентность: повтор по статусу `Completed` возвращает тот же стрим без события очереди; HTTP-ключ идемпотентности не применяется
- Изменяемые данные: `ComposerStream.Status`, `ComposerStream.CompletedAt`
- Публикуемые события: `OrderQueueUpdateType.StreamCompleted` после успешного перехода в `Completed`
- Требования к консистентности: статусы заказов не меняются; очередь асинхронно пересчитывает позиции неразобранных заказов стрима (`Preorder`, `Pending`, `AwaitingPayment`) и выполненных заказов с `ProcessingStreamId` завершённого стрима; выполненные в этом стриме заказы получают `OrderActivityStatus.Removed`

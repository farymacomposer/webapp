# Use case: Отменить заказ

## Полезный результат

Заказ разбора трека больше не подлежит исполнению и не занимает место в очереди. Причина отмены сохранена. Деньги и права зрителя не меняются.

## Участник и момент запуска

- Участник: администратор
- Триггер: администратор решает, что заказ не будет выполнен
- Предусловия: заказ существует

## Входные данные

- `ReviewOrderId` — идентификатор заказа разбора
- `CancelReason` — причина отмены; обязательна

## Наблюдаемый результат

При успехе:

- статус заказа — «отменен»
- зафиксированы момент отмены и причина
- заказ убран из очереди на исполнение
- если заказ был «в работе», слот «сейчас в работе» свободен: момент взятия в работу и стрим обработки сброшены
- категория очереди сброшена
- транзакции заказа не изменяются, возврата средств нет
- погашенные права (жетоны) остаются погашенными
- в ответе возвращается отменённый заказ

При невозможности выполнения:

- заказ не найден → ошибка «заказ не найден»
- статус «выполнен» → ошибка «невозможно отменить заказ»
- участник не администратор → отказ в доступе

## Бизнес-правила

1. Отменить можно заказ в статусе «предзаказ», «ожидает оплаты», «ожидает взятия в работу» или «в работе». Тип заказа и факт оплаты на это не влияют.
2. Замороженный заказ в допустимом статусе можно отменить. Признак заморозки при отмене не снимается.
3. Отмена не создаёт, не изменяет и не удаляет транзакции. Возврата средств нет.
4. Отмена не восстанавливает погашенное право на заказ.
5. Повторный запрос по уже отменённому заказу успешен и ничего не меняет, включая ранее сохранённую причину.

## Различающие сценарии

- Если заказ уже отменён, система возвращает его без изменений.
- Если заказ выполнен, система отказывает.
- Если заказ «в работе», после отмены его можно заменить следующим взятием в работу.
- Если заказ «ожидает взятия в работу» (в том числе оплаченный), после отмены он исчезает из очереди, платежи остаются.
- Если заказ заморожен и ещё не выполнен, отмена проходит так же, как для незамороженного.

## Принятые ограничения

- Бизнес-ограничения: отмена не влияет на транзакции и не возвращает средства; права не восстанавливаются.
- Технические ограничения: операцию запускает только администратор.
- Вне scope: возврат денег, отмена или восстановление прав, отмена заказа зрителем.

## Основания спецификации

### Решения

- Отмена заказа не влияет на транзакции, возврата средств не происходит.

### Факты

- Операция есть в API заказов разбора и доступна администратору.
- Допустимые статусы для перехода в «отменен»: предзаказ, ожидает оплаты, ожидает взятия в работу, в работе.
- Уже отменённый заказ возвращается без повторного применения отмены.
- Выполненный заказ отменить нельзя.
- При отмене сбрасываются стрим обработки, момент взятия в работу и категория очереди; очередь получает событие отмены заказа.
- Если отменяли заказ «в работе», очередь обновляет состояние приоритетов по последнему взятому заказу.
- Транзакции и погашение права в этой операции не изменяются.
- Причина отмены сохраняется у заказа; в текущем ответе API поля причины и момента отмены нет.

### Предположения

- Пустая причина отмены не считается допустимой на уровне контракта, даже если транспорт пропустит пустую строку.

### Открытые вопросы

- Нет.

## Примеры приёмки

### Отмена оплаченного заказа в очереди

Дано:

- донатный заказ в статусе «ожидает взятия в работу»
- по заказу есть платёжные транзакции

Когда:

- администратор отменяет заказ с причиной

Тогда:

- статус заказа — «отменен»
- причина и момент отмены сохранены
- заказ не занимает место в очереди на исполнение
- набор и суммы транзакций те же, что до отмены

### Повторная отмена

Дано:

- заказ уже в статусе «отменен» с причиной A

Когда:

- администратор снова отменяет тот же заказ с причиной B

Тогда:

- операция успешна
- причина остаётся A
- транзакции не меняются

### Отмена заказа в работе

Дано:

- заказ в статусе «в работе»

Когда:

- администратор отменяет заказ с причиной

Тогда:

- статус заказа — «отменен»
- слот «сейчас в работе» свободен
- другой ожидающий заказ можно взять в работу

### Отказ для выполненного заказа

Дано:

- заказ в статусе «выполнен»

Когда:

- администратор пытается отменить заказ

Тогда:

- заказ остаётся выполненным
- система сообщает, что отменить заказ нельзя

## Техническая привязка — опционально

- Точка входа: `POST api/ReviewOrder/Cancel`
- Авторизация: роль администратора
- Транзакционная граница: одно сохранение состояния заказа; очередь обновляется после сохранения
- Идемпотентность: повтор по уже отменённому заказу возвращает тот же заказ без записи; HTTP-идемпотентность по ключу не используется
- Изменяемые данные: статус, момент отмены, причина, категория очереди, стрим обработки, момент взятия в работу
- Публикуемые события: обновление очереди «заказ отменён»
- Требования к консистентности: после успеха заказ в хранилище отменён, а очередь больше не считает его активным

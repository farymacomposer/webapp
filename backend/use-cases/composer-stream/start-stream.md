# Use-Case: Запустить стрим

## Эндпоинт

- Метод: `POST`
- Путь: `/api/ComposerStream/StartStream`

## Что делает

Переводит стрим из `Planned` в `Live` и фиксирует время старта (`StartedAt = UtcNow`).

## Слои

- API:
  - требует авторизацию композитора (`AuthorizeComposer`);
  - принимает `StartStreamRequest`.
- Application (`ComposerStreamService`):
  - загружает стрим по `ComposerStreamId`;
  - допускает запуск только из `Planned`;
  - при повторном вызове для `Live` возвращает текущий стрим без изменений;
  - проверяет, что другого `Live` стрима нет;
  - переводит стрим в `Live`, выставляет `StartedAt`, сохраняет изменения и публикует событие.

## Входные данные

- Body: `StartStreamRequest`
  - `ComposerStreamId` (`long`) - идентификатор стрима.

## Предусловия

- Пользователь должен быть авторизован как композитор.
- Стрим с указанным `ComposerStreamId` должен существовать.
- Стрим должен быть в статусе `Planned`, либо уже быть `Live` для идемпотентного повторного вызова.
- В системе не должно быть другого активного `Live` стрима.

## Что можно

- Запустить стрим в статусе `Planned`.
- Повторно вызвать запуск для уже `Live` стрима без побочных эффектов.

## Что нельзя

- Запустить несуществующий стрим.
- Запустить стрим в статусе `Completed` или `Canceled`.
- Запустить второй стрим, пока другой стрим уже находится в статусе `Live`.

## Результат и постусловия

- Успешный ответ: `200 OK`.
- Тело: `StartStreamResponse`.
- После первого успешного запуска:
  - `Status = Live`;
  - `StartedAt` заполнено текущим UTC-временем.

## События и идемпотентность

- При первом успешном переходе в `Live` публикуется `ComposerStreamChangedEvent` с типом `StreamStarted`.
- Повторный вызов для уже `Live` стрима идемпотентен:
  - состояние стрима не меняется;
  - событие повторно не публикуется.

## Ошибки

- Если стрим не найден или находится в недопустимом статусе, сервис выбрасывает `ComposerStreamException`, и API сейчас возвращает HTTP `666`.
- Если уже существует другой `Live` стрим, сервис выбрасывает `ComposerStreamException`, и API сейчас возвращает HTTP `666`.

## Текущая реализация vs целевое поведение

- Текущая реализация уже гарантирует инвариант: одновременно допускается не более одного `Live` стрима.
- В коде есть TODO про правило даты старта. Сейчас **не** проверяется, что `EventDate` совпадает с текущей UTC-датой.
- Если в будущем будет введено правило `EventDate == today`, его нужно описывать как отдельный доменный контракт после реализации или явного продуктового решения.

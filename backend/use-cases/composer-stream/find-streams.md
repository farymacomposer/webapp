# Use-Case: Получить список стримов за период

## Эндпоинт

- Метод: `GET`
- Путь: `/api/ComposerStream/FindStreams`

## Что делает

Возвращает список стримов, у которых `EventDate` попадает в диапазон от `DateFrom` до `DateTo` включительно.

## Слои

- API:
  - авторизация не требуется;
  - принимает `FindStreamsRequest`;
  - валидирует, что `DateFrom <= DateTo`.
- Application (`ComposerStreamService`):
  - передает диапазон в query-слой без дополнительной валидации.
- Infrastructure (`ComposerStreamQueries.Find`):
  - фильтрует по `EventDate >= DateFrom && EventDate <= DateTo`.

## Входные данные

- Query-параметры:
  - `DateFrom` (`DateOnly`) - начало периода.
  - `DateTo` (`DateOnly`) - конец периода.

## Предусловия

- Запрос должен пройти API-валидацию.

## Что можно

- Запрашивать любой период, где `DateFrom <= DateTo`.
- Получать пустой список, если стримов в диапазоне нет.
- Получать несколько стримов, если несколько `EventDate` попадают в диапазон.

## Что нельзя

- Передавать период, где `DateFrom > DateTo`, если используется API-контракт запроса.

## Результат и постусловия

- Успешный ответ: `200 OK`.
- Тело: `FindStreamsResponse`.
- Сценарий только читает данные:
  - не меняет состояние стримов;
  - не публикует событий.

## События и идемпотентность

- Сценарий read-only.
- Повторные вызовы с теми же параметрами не создают побочных эффектов.

## Ошибки

- Если `DateFrom > DateTo`, API-запрос не проходит валидацию.

## Текущая реализация vs целевое поведение

- На уровне API перевернутый диапазон считается некорректным запросом.
- При прямом вызове application/query без API-валидации перевернутый диапазон не вызывает бизнес-ошибку: текущая логика просто возвращает пустой результат.

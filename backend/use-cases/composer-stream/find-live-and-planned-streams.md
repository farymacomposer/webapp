# Use-Case: Получить текущий и запланированные стримы

## Эндпоинт

- Метод: `GET`
- Путь: `/api/ComposerStream/FindLiveAndPlanned`

## Что делает

Возвращает:
- стримы в статусе `Live`;
- стримы в статусе `Planned` с датой `EventDate >= today`.

## Слои

- API:
  - авторизация не требуется;
  - не принимает входных параметров.
- Application (`ComposerStreamService`):
  - делегирует получение списка в query-слой.
- Infrastructure (`ComposerStreamQueries.FindLiveAndPlanned`):
  - использует `DateTimeService.Today`;
  - возвращает `Live`;
  - возвращает `Planned`, если `EventDate >= today`.

## Входные данные

- Входные параметры не требуются.

## Предусловия

- Дополнительных предусловий нет.

## Что можно

- Получить актуальные для UI стримы: текущий и будущие.
- Получить пустой список, если подходящих стримов нет.

## Что нельзя

- Получить `Completed` или `Canceled` стримы.
- Получить запланированные стримы на прошедшие даты.

## Результат и постусловия

- Успешный ответ: `200 OK`.
- Тело: `FindLiveAndPlannedStreamsResponse`.
- Сценарий только читает данные:
  - не меняет состояние стримов;
  - не публикует событий.

## События и идемпотентность

- Сценарий read-only.
- Повторные вызовы не создают побочных эффектов.

## Ошибки

- Специальные бизнес-ошибки для этого сценария текущим кодом не предусмотрены.

## Текущая реализация vs целевое поведение

- Порог `today` берется из `DateTimeService`, то есть из текущей UTC-даты, а не из локального времени клиента.
- Порядок элементов в ответе текущим кодом **не гарантирован**: `ComposerStreamQueries.FindLiveAndPlanned()` не задает явную сортировку.

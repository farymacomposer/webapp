# Use-Case: Создать стрим

## Эндпоинт

- Метод: `POST`
- Путь: `/api/ComposerStream/CreateStream`

## Что делает

Создает новый стрим в статусе `Planned` с заданными `EventDate` и `Type`.

## Слои

- API:
  - требует авторизацию композитора (`AuthorizeComposer`);
  - принимает `CreateStreamRequest`;
  - валидирует, что `EventDate` не в прошлом относительно `DateTime.UtcNow`;
  - валидирует, что `Type != Unspecified`.
- Application (`ComposerStreamService`):
  - находит пользователя из токена;
  - создает стрим;
  - сохраняет изменения;
  - публикует `ComposerStreamChangedEvent` с типом `StreamCreated`.
- Infrastructure:
  - уникальность обеспечивается индексом по `EventDate`;
  - `ComposerStreamStore` дополнительно не допускает `Type == Unspecified`.

## Входные данные

- Body: `CreateStreamRequest`
  - `EventDate` (`DateOnly`) - дата стрима.
  - `Type` (`ComposerStreamType`) - тип стрима.

## Предусловия

- Пользователь должен быть авторизован как композитор.
- Пользователь из токена должен существовать в системе.
- В запросе должна быть указана сегодняшняя или будущая дата.
- Тип стрима не должен быть `Unspecified`.
- В системе не должно быть другого стрима на ту же дату.

## Что можно

- Создать стрим на сегодня или будущую дату.
- Повторно использовать любой поддерживаемый тип, кроме `Unspecified`, если дата уникальна.

## Что нельзя

- Создать стрим на прошедшую дату.
- Создать стрим с типом `Unspecified`.
- Создать второй стрим на ту же `EventDate`, даже если `Type` отличается.

## Результат и постусловия

- Успешный ответ: `200 OK`.
- Тело: `CreateStreamResponse`.
- После успешного вызова:
  - создается новый стрим;
  - `Status = Planned`;
  - `StartedAt = null`;
  - `CompletedAt = null`.

## События и идемпотентность

- При первом успешном создании публикуется `ComposerStreamChangedEvent` с типом `StreamCreated`.
- Операция не является идемпотентной: повторный вызов с той же датой приводит к ошибке, а не к возврату уже существующего стрима.

## Ошибки

- Некорректный запрос не проходит API-валидацию:
  - прошедшая дата;
  - `Type == Unspecified`.
- Если пользователь не найден, сервис выбрасывает `ComposerStreamException`, и API сейчас возвращает бизнес-ошибку с HTTP `666`.
- Если нарушена уникальность по `EventDate`, сервис преобразует конфликт БД в `ComposerStreamException`, и API сейчас возвращает HTTP `666`.

## Текущая реализация vs целевое поведение

- Запрет прошедшей даты существует только на уровне API-запроса и не дублируется в `ComposerStreamService`.
- При прямом вызове ниже API `Type == Unspecified` все равно отсекается в `ComposerStreamStore`, но уже не как validation error, а как исключение из application/infrastructure слоя.

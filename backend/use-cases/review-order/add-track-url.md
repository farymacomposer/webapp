# Use-Case: Добавить или изменить ссылку на трек

## Эндпоинт

- Метод: `POST`
- Путь: `/api/ReviewOrder/AddTrackUrl`

## Что делает

Добавляет или обновляет `TrackUrl` в заказе.
Если заказ находится в статусе `Preorder`, операция переводит его в `Pending`.

## Слои

- API:
  - требует роль администратора (`AuthorizeAdmins`);
  - принимает `AddTrackUrlRequest`;
  - валидирует, что `TrackUrl` передан и является корректным URL.
- Application (`ReviewOrderService`):
  - загружает заказ;
  - допускает операцию для `Preorder`, `Pending` и `InProgress`;
  - обновляет `TrackUrl`;
  - переводит `Preorder -> Pending`;
  - сохраняет изменения и публикует событие.

## Входные данные

- Body: `AddTrackUrlRequest`
  - `ReviewOrderId`.
  - `TrackUrl` - обязательный валидный URL.

## Предусловия

- Пользователь должен быть авторизован как администратор.
- Заказ должен существовать.

## Что можно

- Добавить или изменить ссылку для заказа в `Preorder`, `Pending` или `InProgress`.
- Перевести заказ из `Preorder` в `Pending` при добавлении ссылки.
- Обновить `TrackUrl` без смены статуса для заказов в `Pending` и `InProgress`.

## Что нельзя

- Изменять ссылку у несуществующего заказа.
- Изменять ссылку у заказа в `Completed` или `Canceled`.

## Результат и постусловия

- Успешный ответ: `200 OK`.
- Тело: `AddTrackUrlResponse`.
- Клиент получает `ReviewOrderDto`.
- Внутренние postconditions:
  - `TrackUrl` обновлен;
  - `Status` меняется только в случае `Preorder -> Pending`.

## События и идемпотентность

- Операция не является идемпотентной в HTTP-смысле: повторный вызов может менять `TrackUrl`.
- При успешном вызове публикуется `ReviewOrderChangedEvent`:
  - `UpdateType = TrackUrlAdded`;
  - `PreviousStatus =` исходный статус заказа.

## Ошибки

- Некорректный запрос не проходит API-валидацию, если `TrackUrl` отсутствует или не является валидным URL.
- Если заказ не найден или находится в недопустимом статусе, сервис выбрасывает `ReviewOrderException`, и API сейчас возвращает HTTP `666`.

## Текущая реализация vs целевое поведение

- Текущая реализация допускает `AddTrackUrl` не только для `Preorder`, но и для `Pending` и `InProgress`.
- Смена persisted-статуса происходит только для перехода `Preorder -> Pending`; в остальных допустимых случаях операция выполняется без смены статуса.

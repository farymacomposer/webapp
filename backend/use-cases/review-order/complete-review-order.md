# Use-Case: Выполнить заказ

## Эндпоинт

- Метод: `POST`
- Путь: `/api/ReviewOrder/CompleteReviewOrder`

## Что делает

Завершает заказ, создает сущность разбора (`Review`), записывает рейтинг и время завершения.

## Слои

- API:
  - требует роль администратора (`AuthorizeAdmins`);
  - принимает `CompleteReviewOrderRequest`;
  - валидирует, что `Rating` находится в диапазоне `0..26`.
- Application (`ReviewOrderService`):
  - загружает заказ;
  - допускает выполнение только для `InProgress`;
  - находит пользователя из токена;
  - создает `Review`;
  - выставляет `CompletedAt`, `Status = Completed`;
  - сохраняет изменения и публикует событие.
- Infrastructure (`ReviewStore`):
  - при прямом вызове ниже API дополнительно гарантирует только неотрицательный рейтинг.

## Входные данные

- Body: `CompleteReviewOrderRequest`
  - `ReviewOrderId`.
  - `Rating` - от `0` до `26`.

## Предусловия

- Пользователь должен быть авторизован как администратор.
- Пользователь из токена должен существовать.
- Заказ должен существовать и быть взят в работу.

## Что можно

- Выполнить заказ в статусе `InProgress`.
- Повторно вызвать сценарий для уже `Completed` заказа без побочных эффектов.

## Что нельзя

- Выполнить несуществующий заказ.
- Выполнить заказ в `Preorder`, `Pending` или `Canceled`.
- Передавать рейтинг вне диапазона `0..26` через HTTP API.

## Результат и постусловия

- Успешный ответ: `200 OK`.
- Тело: `CompleteReviewOrderResponse`.
- Клиент получает:
  - `ReviewOrder: ReviewOrderDto`;
  - `ReviewId: long`.
- После первого успешного вызова:
  - `Status = Completed`;
  - `CompletedAt` заполнено;
  - создан `Review`.

## События и идемпотентность

- Повторный вызов для уже `Completed` заказа идемпотентен:
  - persisted-состояние не меняется;
  - событие повторно не публикуется.
- При первом успешном вызове публикуется `ReviewOrderChangedEvent`:
  - `UpdateType = OrderCompleted`;
  - `PreviousStatus =` исходный статус заказа.

## Ошибки

- Некорректный HTTP-запрос не проходит API-валидацию, если `Rating` вне диапазона `0..26`.
- Если заказ не найден, находится в недопустимом статусе или пользователь не найден, сервис выбрасывает `ReviewOrderException`, и API сейчас возвращает HTTP `666`.

## Текущая реализация vs целевое поведение

- Для HTTP-контракта рейтинг ограничен диапазоном `0..26`.
- При прямом вызове ниже API ограничение отличается: `ReviewStore` явно запрещает только отрицательные значения, но не ограничивает верхнюю границу `26`.
